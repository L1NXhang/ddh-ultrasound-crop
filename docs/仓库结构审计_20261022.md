## 一、结论摘要

1. **最痛的不是"文件多"，而是同一个模型有 3 个线上副本、彼此已经分叉**：`ddh.py` 说自己是 "research core **v2**"，`ddh_v2.py` 说自己是 "v2.**1**"；而**当前产品真正跑的推理代码是第三份——`tools/studio_predictor.py` 里的 `CropNet`**（因为桌面壳启动的是 `tools/crop_studio.py`，不是 `ddh*.py`）。`ddh_v2.py` 被定义为"产品模型结构一致"的训练版本，但没有任何测试或断言守住这一点。结构整理一旦动到这里，风险是**静默的产品精度回归**。
2. **根目录 30 个散落文件里有 3 个是真正的"承重墙"或"真地雷"**：`crop_policy.py` 被整个 `tools/` 22 处 import、且 `tests/portable_paths` 与 `build_portable` 依赖它留在根目录——**不能动**；根目录 `SHA256SUMS.txt` 已经指向**旧版本**（`README.md`、`ddh.py` 校验失败），照它核对发行包会出错；`convert.log` 是 0 字节空壳。
3. **tests/ 里不存在孤儿测试**——31 个 `test_*.py` + 12 个 smoke/辅助脚本全部能对应到被引用的模块；反过来，`tools/` 里**约 45 个模块没有任何测试**，其中 `studio_predictor.py` 例外（有 4 个测试，但没有结构与训练端的一致性断言）。测试与工具的耦合方式是"扁平文件 + `sys.path.insert(tools)`"，这是迁移成本的主要来源。
4. **`.gitignore` 本身没错但有三处硬伤**：`output/`（20+ 张验收截图、1.5MB PNG + `desktop_automation.jsonl`）**没有被忽略、也没被跟踪，却已经真实存在于工作区**；`desktop/runtime/`（774KB WebView2 DLL）被忽略但构建需要它；`.gitignore` 是 **UTF-8 无 BOM**（不是 GBK，用 GBK 读才会乱码，请勿转码）。
5. **`requirements.txt` 只有 4 行、无 lock**，而 `TEST_REPORT.md` 声称"numpy 2.5.2 / Pillow 12.3.0"——**这两个版本不存在**，说明该文件里的版本号是编造或未核实的；`docs/构建与发布.md` 里的 `numpy==1.26.4 Pillow==11.3.0 pyinstaller==6.22.3` 与 requirements 之间没有任何引用关系。

**如果一项都不改，最痛的是**：新人/未来的你自己打开仓库，会看到 3 份互相声称"我是 v2"的模型代码文件、33 篇无时间戳命名规则的文档、2 个都不反映当前状态的 `SHA256SUMS.txt` 和 `TEST_REPORT.md`，**只能在 7 份 README/手册之间交叉比对才能判断哪份是现役**——而这个判断错误会导致训练出一个与产品不兼容的权重。

## 七、"如果一个都不改"的代价

1. **新人 30 分钟内无法回答"我现在该改哪个文件"**：`ddh.py`（自称 v2）、`ddh_v2.py`（自称 v2.1）、`tools/studio_predictor.py`（产品真实推理）三选一，而 README 只提第一个。
2. **发布前校验会被这个仓库自己骗**：`SHA256SUMS.txt` 对 `README.md` 与 `ddh.py` 报 FAIL；`TEST_REPORT.md` 报"12 tests OK"而实际 116 项。**任何"看起来在自检"的东西都已经过期**。
3. **下一次 `git add -A` 会把 `output/` 里 20 张验收截图与 `desktop_automation.jsonl` 推向公开仓库**——这批文件（协作审核界面、桌面自动化记录、1.5MB 的大图）**没有进 `.gitignore`**，`data/` 的忽略规则管不到它。**这是唯一一处"现在不改、下次就可能发生"的结构问题**，也是"现在就该做 #1"的核心理由。
4. 一旦 `ddh_v2.py` 的 `CropNet` 与 `studio_predictor.py` 在无人察觉的情况下分叉，产品会加载一个"训练时结构不同"的权重，**报错在最好的情况下，静默精度下降在最坏的情况下**——而当前没有任何测试守这个边界。
5. **三个"看起来像自检"的东西全部不可信**：根 `SHA256SUMS.txt`（FAIL）、`TEST_REPORT.md`（12 tests）、`docs/技术栈与原理.md` 的 14 处 `ddh.py:行号`（代码一动即错）。它们比没有更糟，因为**会让人以为已经核对过**。
