# 边缘信息标注回传校验

两名成员仍在标注。今天先接通回传后的检查与复核流程，尚未进行新增训练。

## 使用

1. 保留成员原始导出文件，将最终JSONL放入 `data/cleanup_returns/`。
2. 在项目根目录运行 `python tools/audit_cleanup_returns.py --render`。
3. 查看 `data/reports/cleanup_returns_20261014/报告.md`，先处理无效记录和同人版本冲突。
4. 再查看双人分歧对照图和拿不准的样本，确定后另行形成批准标签版本。

也可以通过 `--inputs 文件1.jsonl 文件2.jsonl` 明确指定输入，避免把旧快照误作为最终版本。

## 检查内容

- 只接受正式v2任务清单中的任务、成员和图片，核对原始路径、包内别名、指纹与尺寸。
- 核对schema、坐标空间、人工来源、布尔状态和备注；缺失标签不会自动变成“没有覆盖物”。
- 核对窗口、覆盖物和最终框都是有效原图整数坐标，最终框必须在window内部。
- 最终框仍含覆盖物时，必须有待复核状态与原因；覆盖物完全位于window外也会提示复核。
- 同人相同记录的重复快照去重，忽略导出来源与时间；标注内容不同则隔离，不按文件顺序覆盖。
- 重新解码原始图片并核对像素指纹，发现图片被换掉或缺失时不接收该记录。
- 对双方都回传且通过校验的共同图片，对比window四边、clean_box四边、覆盖物有无与一一对应的框。

覆盖物按类型和IoU建立二分匹配，采用增广路径处理多个候选，避免按列表顺序或简单贪心造成误判。
默认window边差8px、clean_box边差16px、覆盖物匹配IoU 0.5，仅用于安排复核优先级，不是临床合格标准。
框的一致性也不能证明解剖结构完整保留。

## 输出

- `audit.json`：每任务应回传、已收到、通过数量、遗漏ID、无效记录、版本冲突及复核队列。
- `validated_proposals.jsonl`：格式和来源校验通过的建议，仍保持 `approved_for_training=false`。
- `报告.md`：摘要、待复核记录、当前对照图链接。
- `对照_*.png`：共同图存在分歧时并排展示两人的蓝色window、绿色clean_box和黄色覆盖物。

输出不修改原始导出、正式标签、现用模型或预留清单；校验通过不会自动触发训练。
报告只链接本次生成的对照图，不根据旧图片文件推断当前分歧。
