### 但要说清楚：裁切图只能给 crop，给不了 safe_box

- `crop`（人工偏好的裁剪区间）→ 可以从你的裁切图反推 ✓

  方案文档写得很明确：只靠 crop 标签，模型能学会"像多数标签那样裁"，但无法区分

  安全辅助头学不到东西。

## 6 标注字段速查（坐标一律是原图像素，不是归一化）

| 字段 | 含义 | 谁写 |
| --- | --- | --- |
| `id` `path` | 唯一编号、相对 `--root` 的路径 | 已生成 |
| `window` | 成像窗口 xyxy，每图必需 | 人工（可用模板） |
| `crop` | 偏好裁剪的 top/bottom，非标准切面写 null | 人工（可从裁切图反推） |
| `safe_box` | 必保结构联合外接框 xyxy | 老师定义 |
| `quality` | 1 可建议、0 应拒绝、null 未知 | 人工 |
| `style_group` | 界面外观组（按分辨率+界面归组） | 人工核实 |
| `collect_group` | **采集来源**（余/吴/张/胡/阳） | 已自动填好 |
| `source_group` | **同一序列/同一批次**；填错会把图并成一组 | 留空，除非确知是同一次检查 |
| `graf_type` | 已有分型，不推断 | 胡目录已填 |
| `human_modified` | 真实人工是否改动过模型建议 | 以后评估用 |

两个容易混的字段：`collect_group` 是你给我的文件夹（来源），`source_group` 的语义是
"同一序列/同一批次"——`ddh.py audit` 会把同一个 `source_group` 并进同一个泄漏组，
所以拿文件夹名填 `source_group` 会把整批并成一组、`split` 直接报错。
我已经把文件夹挪到 `collect_group`、把 `source_group` 清空（实测：修正前 195 张并成 1 组，
修正后 195 组）。将来如果你确知某几张是同一次检查（同患者同次），才在那几行填 `source_group`。

## 7 从标注到模型：完整命令序列

```bat
:: 0) 把标注好的清单另存为 data/annotations.jsonl
:: 1) 近重复审核与分组（先看 pairs.json 再决定是否手工合并）
python ddh.py audit --manifest data/annotations.jsonl --root data --output data/grouped.jsonl --report data/pairs.json
:: 2) 审核通过后划分（--reviewed 必须真的审核过才加；至少 10 个非留出组）
python ddh.py split --manifest data/grouped.jsonl --output data/split.jsonl --reviewed --seed 42
:: 3) 训练（先跑 A 再跑 B；CPU 调试加 --device cpu）
python ddh.py train --stage window --manifest data/split.jsonl --root data --output runs/window.pt --size 640 --batch 2 --epochs 40 --patience 8 --device cuda
python ddh.py train --stage crop   --manifest data/split.jsonl --root data --output runs/crop.pt   --size 384 --batch 8 --epochs 80 --patience 12 --device cuda
:: 4) 校准（在 val 拟合阈值，在 calib 独立核查；组数不够会 enabled=false，这是正常的保守结果）
python ddh.py calibrate --manifest data/split.jsonl --root data --window-checkpoint runs/window.pt --crop-checkpoint runs/crop.pt --output runs/calibration.json --device cuda --samples 16 --margin 0.02
:: 5) 评估与单图推理
python ddh.py evaluate --manifest data/split.jsonl --root data --window-checkpoint runs/window.pt --crop-checkpoint runs/crop.pt --calibration runs/calibration.json --output runs/test.json --device cuda
python ddh.py predict --image data/images/余/50918177.jpg --style layout_01 --window-checkpoint runs/window.pt --crop-checkpoint runs/crop.pt --calibration runs/calibration.json --output runs/one.json --preview runs/one_candidate.png --device cuda
```

第一次正式训练会联网下载 COCO 与 ImageNet 预训练权重（约 100MB，一次即可）。
`--no-pretrained` 只用于代码测试，正式训练不要禁用。

2. **定规则**：老师确认 safe_box 定义、quality 定义、容差，以及你的裁切口径。
3. **全量 window**：确认模板（869 张一次套用）+ 211 张人工，一次做完。
4. **crop 标签**：继续按你现有的方式裁图，每裁完一批我就用 `tools/match_crops.py` 反推成
   `[top, bottom]`（230 张已验证 100% 成功）。
5. **safe_box 与 quality**：这两个**不能**从裁切图反推。train 先补 200–300 张 safe_box；
   val/calib/test 尽量全补（约 300 张），否则校准一定 `enabled=false`。这一块才是真正需要
   老师/学生手工标注的部分，建议先从这里排期。
6. **正式训练与评估**，按版本保存 split.jsonl、日志、模型 SHA256、校准 JSON。

## 9 已知的坑（代码审查结论）

- **文档承诺但代码里没有**：固定位置中位数基线（消融矩阵第 1 项）、
  "空间头只裁剪不加辅助任务"的开关（消融矩阵第 3 项）。要跑这两项需要补代码。
- 步骤 A 的选点指标（top-1 框的 1−IoU）与部署门控（分数≥0.8 且恰好一个框）不一致，
  可能选出"平均 IoU 好但大量图被拒绝"的检查点，建议补一个"合格窗口率"指标。
- 校准用的特征参考库是在**真窗口**上建的，推理时用的是**检测窗口**，两者不一致会让
  距离阈值失真。
- 只靠 crop 标签时，Lkeep 与 Lsafe 自动关闭：模型学得到人工偏好，但学不到"哪些结构不可缺失"。
- 合成测试产生的权重（`smoke_output`、`bench_out`）**绝不能**用于真实数据，我已删除。
