# 批量裁剪工具（本地版）使用说明

> 2026-10-14 已新增支持选择目录、自动批量、四边人工审核和可选 ZIP 的裁剪工作台。日常使用请参考[裁剪工作台使用说明](裁剪工作台使用说明.md)。下文保留旧版 `crop_app.py` 的操作说明与当时的实验记录；历史精度数字不作为新版独立测试结果。

工具文件：`tools/crop_app.py`
界面文件：`tools/webapp/crop.html`（浏览器打开，不用装任何东西）

---

## 一、它做什么

选一个**装满待裁图片的文件夹** → 工具逐张给出**成像窗口**和**上下裁剪线** → 你按 `Enter` 接受、
或拖线微调 → 工具把结果写盘。**不需要服务器、不需要联网、图片不出本机。**

**窗口是逐图检测的，不用模板**（`tools/detect_window.py`，算法见第六节）。
实测：老设备 862 张四边 ≤4px 命中率 94%，新设备 89 张（以人工确认窗口为真值）93%
——其中以前最费手的**右边界从 26% 提升到 97%**。裁剪线来自训练好的模型（`runs_v2/crop.pt`）。

---

## 二、怎么用

```bash
cd /d/ddhmodel/ddh_multidevice_v2
.venv\Scripts\activate
python tools\crop_app.py --folder "D:\待裁的图片文件夹" --out "D:\裁剪结果"
```

然后浏览器打开 **http://127.0.0.1:8770**（终端会打印地址）。

**界面操作**（每张 3–5 秒）：

| 按键 | 作用 |
| --- | --- |
| **Enter** | 保存并进入下一张（最常用） |
| 拖动**绿线**/**蓝线** | 调整上下边界 |
| **↑** / **↓** | 微调 1 像素（Shift 是 10 像素） |
| **W** | 切到窗口框模式（**只在红框明显不对时用**，改完按 C 切回） |
| **C** | 回到裁剪线模式 |
| **A** | 绿线恢复到模型预测值 |
| **K** | 跳过这张（图像有问题时） |

左侧会显示：进度、当前文件、窗口与裁剪值、算法的自我提示（比如"内容贴图像边缘"，这时建议用 W 看一眼红框）。

## 三、输出（每次 Enter 立刻写盘）

```
<输出目录>/
├─ cropped/<原文件名>.png     裁好的图（原图像素、不缩放）
├─ annotated/<原文件名>.png   原图 + 红框(窗口) + 绿线(上边界) + 蓝线(下边界)
└─ results.jsonl              每张记录：窗口、裁剪框、是否人工微调、算法提示、耗时
```

- **裁剪图** = 窗口宽度 × 你确认的上下边界，**不做任何缩放**，保留原始像素；
- **标注图**是给老师看的验收材料，也是"这次裁了什么"的凭证；
- **results.jsonl** 可直接用作下一轮训练数据（含 `modified` 字段，天然就是"人工修改率"）。

**断点续做**：关掉再打开同一个 `--folder`，已完成的不再出现（读 `results.jsonl` 判断）。

## 四、已验证

**窗口检测精度**（以人工确认的窗口为真值，四边各自误差 ≤4px 的比例）：

| 数据集 | 左 | 上 | 右 | 下 | 四边都 ≤4px | 四边都 ≤8px |
| --- | --- | --- | --- | --- | --- | --- |
| 老设备 862 张 | 100% | 100% | 99% | 95% | 94% | 94% |
| 新设备 89 张 | 99% | 98% | **97%** | 100% | **93%** | 94% |

新设备右边界在改进前只有 26%（中位偏宽 71px，全靠人工往回拖），现在 97%。

- 端到端实测通过：预测 → 保存 → 两个文件都写对（裁剪图 459×481 = 窗口宽 459 × 裁剪高 481）；
- 新版算法在新设备一张图上：工具给出 `[123,28,896,759]`，人工确认 `[123,28,895,759]`，四边全部 ≤1px；
- 标注图目视核对：红框贴合成像区、绿线在皮下层下方、蓝线包住股骨头 ✓
- 队列前进、跳过、断点续做、算法自查标记都正常。

## 五、两种跑法

| 场景 | 命令 |
| --- | --- |
| 正常裁剪（写文件） | `python tools/crop_app.py --folder "<待裁图>" --out "<输出>"` |
| 只看不写（试用/检查） | 加 `--dry-run` |
| CPU 机器 | 加 `--device cpu`（慢一些） |
| 不想要额外安全边距 | 加 `--margin 0`（默认 0.02 = 窗口高度的 2%） |

## 六、窗口检测怎么做的（为什么不用模板）

四步，全部逐图计算，不含任何设备/分辨率假设：

1. **内容掩膜**：4×4 小块里"非纯黑像素占比 > 5%"的块算内容。阈值取低是故意的——
   成像区顶部常有一条近乎黑的窄带（实测行灰度只有 5~16），阈值调高会把它切掉。
2. **连通域**：取最大连通域的外接框作为粗框，顺带把界面上的文字、刻度、示意图排除掉。
3. **左右边界（走廊 + 吸附）**：各设备的共同结构是「成像区 → 黑走廊 → 界面元素」。
   从内容内部向外扫，遇到连续 2 列占用率 < 35% 的走廊就停——走廊之后的干扰
   （深度标尺竖线、TGC 渐变条，实测占用率 37%~54%）根本扫不到。
   这一点是关键：老设备窗口右缘本身是渐隐的（36%~57%），与 TGC 条数值完全重叠，
   任何静态阈值都分不开；只有"从内部向外找走廊"才能区分。
   走廊只负责判断"是哪条边"，再在 ±12px 邻域里取梯度最大者吸附到像素级。
4. **上下边界**：从粗框边缘向内扫，取第一条占用率 > 20% 的行。方向很重要——
   窗口底部常有约 130px 的暗淡区（行灰度 0.6~7.8），从内部向外走会被它截断；
   而窗前/窗后的文字行占用率只有 3%~8%，低于阈值不会被选中。

已知边界情况（都不影响裁剪口径）：新设备顶部边界处在近乎黑窄带里，人工习惯切在
证据出现后约 3px，算法切在证据处（差异 ≤4px，占 98%）；老设备约 5% 的图窗口底部
包含一整片黑区（人工口径如此），算法无法从像素判断，会把下边界抬高。

## 七、注意

1. **原图永不被修改**——工具只读原图，所有输出都写到 `--out` 目录；
2. 新设备/没见过的界面**也能用**，因为窗口是现场检测的；但如果是完全陌生的设备，
   建议先用 `--dry-run` 试跑 20 张看看效果；
3. 若某张的窗口明显不对，按 `W` 自己框一下（红框决定输出宽度，所以要准）；
4. 裁剪线的口径来自训练数据（"切在皮下组织层下方、保留该层"）。换医院/设备后如果要改口径，
   需要重新标一批数据再训练。
