## 一、DDH 标准切面的结构要求（文献要点）

Graf 法要求"标准冠状切面"上**同时**看到以下结构，缺一不可：

| 结构 | 说明 |
| --- | --- |
| **髂骨线** | 髂骨骨性轮廓，呈**平直的水平强回声线**，是测量基线 |
| **髋臼骨性顶** | 从髂骨下缘到骨性缘的斜坡，α 角来源 |
| **髋臼软骨顶 / 盂唇** | 骨性缘外侧的软骨与强回声盂唇（β 角来源） |
| **股骨头** | 软骨性股骨头，应呈**无回声**、显示**最大径** |
| **三叉软骨** | 髂骨/坐骨/耻骨之间的软骨联合，确认深度与切面正确 |
| 关节囊、髋臼内壁 | 辅助确认 |

**Graf 三点校验**（确认切面居中）：① 髂骨下缘；② 髋臼骨性缘（凹陷转凸的转折点）；③ 盂唇中心。

> ⚠️ **关键例外**：脱位髋（Graf III/IV 型）**不可能**在同一张图上同时看到这三点
> （股骨头已移到另一平面）。所以"看不到全部结构就打 quality=0"这条规则，
> 会把最严重的病例错误地拒掉——这是在定 quality 口径时必须写进去的例外。

**角度定义**：α 角 = 髂骨垂直皮质（基线）与骨性顶连线；β 角 = 髂骨基线与盂唇连线。

## 二、AI 类研究怎么做 ROI（文献要点，用于校准我们的做法）

| 工作 | 做法 | 对我们的意义 |
| --- | --- | --- |
| DDH-Net（MDPI） | **目标检测引导 ROI 提取** + U-Net 分割 + 角度测量 | 与我们的两阶段方案一致 ✓ |
| YOLOv8 关键点（BMC） | 10 年经验医师用 LabelMe 手工裁 ROI，**每个 ROI 必须包含 5 个关键解剖标志**，严格限定髋关节区、排除背景与伪影 | 支持我们的"紧贴髋关节裁剪"口径 ✓ |
| DDH 端到端（Research Square） | ROI 提取去除背景与设备界面；黑像素校验；缩放到固定尺寸 | 与我们"去黑边/去界面"的目标一致 |
| **QualityDDH（Springer）** | 结构分割 + **Checklist I（解剖识别）+ Checklist II（可用性评估）**；代码开源 | **quality 标签直接采用这个双检查表框架** |
| 中文研究 + 专利 CN119600589A | **最大连通域**自动裁剪，去纯色背景与界面干扰 | 与我们的几何方法同源 |

**结论**：我们"检测器找窗口 + 客观判据验收 + 人工确认"的路线与文献主流一致；
`quality` 建议采用"解剖识别 + 可用性"两张检查表，而不是单一口径。

## 三、新批次（874 张）盘点

**结构**：不是 5 个设备，而是 **3 个主布局 + 约 30 张零散**，5 个子文件夹是"批次"。

| 布局 | 张数 | 说明 |
| --- | --- | --- |
| 1024×768 | **733**（其中 725 张同一布局） | 至少 3–4 种界面变体（`C 60 P Med Gen` / `C 58 P Med Res` / `DR 50 P Low Res` …），说明这台分辨率下混着多台机器 |
| 1260×910 | 93 | **Mindray Resona 7**，图上直接印 α/β 角度值 |
| 1280×960 | 24 | Philips（与老批次同款） |
| 1292×970 / 1552×970 / 1618×1216 / 800×600 | 24 | 零散 |

### ⚠️ 关键结构发现：某台设备的窗口下边界**不是常量**

以 1024×768 那台为例，用坐标网格逐图测量：

- 上边界 ≈ 128、左边界 ≈ 316、右边界 ≈ 775 —— **固定**；
- **下边界在 600 → 732 之间变化**，随扫描深度改变（机器把显示区裁到实际采集深度）。

**后果**：老批次那种"每种布局一个固定模板"的做法在这台设备上**失效**，
必须逐图检测下边界。（老批次 Philips 是固定窗口，所以那时模板法成立。）

## 四、模型在新设备上的表现（跨设备泛化的第一次实测）

用老批次训练出的窗口检测器（40 轮，862 张）直接跑新批次：

| 指标 | 结果 | 解读 |
| --- | --- | --- |
| 恰好一个高分框（≥0.8） | **98/101 = 97%**（分数中位 1.0） | **定位能力强**，能认出"哪里是成像区" |
| 框边缘精度 | 全量 874 张中只有 **190 张（22%）** 通过"框外一圈干净"判据 | **边缘有 5–30 px 偏差**，多数会切到内容 |
| 失败模式 | 出错的图多给 2–4 个框，被"恰好一个"规则正确拦下 | 失败是**可见的**，不是静默的 ✓ |

**结论（要写进任何对外说明）**：

> 检测器在新设备上**能当"建议者"，不能当"标签"**。分数高 ≠ 位置对。
> 高分只是"像窗口"，边缘仍需人工确认——这正是"静默错误"风险的实证，
> 也是为什么必须有客观验收判据 + 人工确认两道关。

产出：`data/reports/new_window_proposals.jsonl`（190 条待抽检）、
`data/reports/new_window_queue.txt`（684 条人工队列）、`data/review/new_accepted_check.png`（抽检图）。

## 五、建议：这批新数据先别拿去训练

它最值钱的地方是**"从未见过的设备"**这个身份。一旦进训练集，就再也无法用它证明跨设备泛化——
而"换设备还能用"恰恰是这个项目对外最硬的卖点。

**建议用途**：当作**跨设备测试集**
1. 抽 150–200 张，人工确认 window + crop（用标注工具，模型先给建议，只改不对的）；
2. 用它回答"模型换设备还准不准"（现在这个数字是**空白的**）；
3. 以后若要把新批次纳入训练，**必须另留一批更新的设备**做测试。

## 六、给《裁切口径》的两条文献依据（可直接抄）

### 1) `safe_box` 建议范围

必保结构 = **髂骨线（含其上方约定的软组织余量）→ 股骨头下缘 / 三叉软骨**，
左右取窗口内的全部宽度。即：把"用于测量 α/β 角的全部解剖要素"完整包住。

### 2) `quality` 建议改成两张检查表（替代原来的 A/B 二选一）

- **Checklist I（解剖识别）**：能否看到 髂骨线、髋臼骨性顶、盂唇、股骨头、（三叉软骨）；
- **Checklist II（可用性）**：清晰度是否足够、切面是否居中（Graf 三点）、有无遮挡或伪影；
- 两张都过 → `quality=1`；任一不过 → `0`；拿不准 → `null`；
- **例外（必须写）**：Graf III/IV 型脱位不要求三点齐全，按"测量要素是否可见"判断。
