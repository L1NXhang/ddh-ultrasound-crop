# 构建与发布

仓库保存代码、测试和文档；安装包、运行库和推理权重通过 GitHub Releases 分发。医学原图、真实标注、逐图评估记录、旧登录口令和本机运行状态不得上传。

## 准备环境

建议在 Windows 10/11 x64 使用 Python 3.11。构建脚本依赖 Pillow，桌面外壳使用 Windows 自带的 .NET Framework C# 编译器；不需要另装完整 Visual Studio。

```powershell
python -m venv data/portable_build/env
data/portable_build/env/Scripts/python.exe -m pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu
data/portable_build/env/Scripts/python.exe -m pip install numpy==1.26.4 Pillow==11.3.0 pyinstaller==6.22.3
```

GPU 构建使用独立的 `data/portable_gpu_build/env`，安装对应的 CUDA 12.1 PyTorch 版本。源码保留 `prepare_gpu_build_env.py` 供已有相同项目环境时复用，普通维护者也可直接创建独立环境并安装相同依赖。

准备兼容的 `runs_v2/crop.pt`，模型文件不提交到 Git。下载并验证固定 WebView2 Runtime：

```powershell
python tools/download_webview_runtime.py
```

桌面构建自动下载固定版本的 Microsoft WebView2 SDK，并核对预先记录的 SHA256。

## 构建完整应用

```powershell
python tools/build_portable.py --variant cpu
python tools/build_portable.py --variant auto --no-archive
```

默认输出位于工作区父目录 `release/`。v0.5.0 CPU 包同时生成便携 ZIP；GPU 版只生成完整应用目录，用于构建安装器，避免额外压缩一个无法直接上传的大 ZIP。

脚本只从明确列出的程序资产复制文件，剥离权重中的研究元数据，检查参数等价性，保存第三方许可证，并生成逐文件 SHA256 清单。已有发行目录和 ZIP 不会自动覆盖。发布源码改动后必须重新冻结后端，不能用旧后端搭配新页面冒充新版本。

## 构建安装程序

从 [Inno Setup 官方下载页](https://jrsoftware.org/isdl.php) 获取编译器。可使用官方 `/PORTABLE=1` 模式放入 `data/installer_toolchain/inno`，使用前核对官方 SHA256 和 Authenticode 签名。本轮使用 Inno Setup 6.7.3；该工具仅作为构建依赖，不进入应用发行目录。

```powershell
python tools/build_installer.py --source ../release/DDH_Crop_0.5.0_Windows_x64_CPU --out ../release/v0.5.0 --compiler data/installer_toolchain/inno/ISCC.exe --variant cpu
python tools/build_installer.py --source ../release/DDH_Crop_0.5.0_Windows_x64_CPU_GPU --out ../release/v0.5.0 --compiler data/installer_toolchain/inno/ISCC.exe --variant auto
```

本次 CPU 和 GPU 都输出单个安装 EXE，分别检查满足 GitHub 单附件小于 2 GiB 的限制。如未来版本超过限制，可追加 --split 生成分卷，分卷上限为 1,900,000,000 字节。脚本再次核对所有输入文件摘要，随后记录安装器文件的大小与 SHA256。

安装器按当前用户安装，不覆盖或删除外部图片与结果目录。项目当前没有代码签名证书，不把 Inno 编译器的签名误认为应用安装器已经签名。

## 发布前验证

```powershell
python -m unittest discover -s tests -p "test_*.py"
python tests/measure_studio_coverage.py
python tests/smoke_studio_browser.py
python tests/smoke_studio_collaboration.py
python tests/smoke_review_https.py
python tests/smoke_portable.py --archive ../release/DDH裁剪工具_Windows_x64_CPU_v0.5.0.zip --expected-device cpu
python tools/audit_publication.py --include-untracked
git diff --check
```

浏览器和安装验证还需单独安装相应测试依赖，例如 Playwright、用于本地测试证书的 cryptography；它们不打入产品。

安装器应在工作区内隔离目录完成安装、启动、预测、协作审核和卸载验证。CPU/GPU 自动版需分别验证 CUDA 路径和隐藏 CUDA 后的 CPU 回退，不以配置选项代替实际运行。

## 上传到 GitHub

1. 检查拟提交清单，排除真实数据、权重、运行库、临时文件和任何凭证。已经被 Git 跟踪的数据必须从索引移除，仅加 `.gitignore` 不会移除旧跟踪项。
2. 以明确文件名暂存代码、测试和公开文档，不用 `git add -A`。
3. 提交并推送，确认远程没有其他人尚未同步的修改，不强制推送。
4. 为对应提交创建 Release 草稿，上传已经验证的安装包、CPU 便携 ZIP 和 SHA256 清单。
5. 下载并检查远程附件摘要／下载可达性，再发布草稿。

GitHub CLI 操作示例：

```powershell
gh release create v0.5.0 --repo L1NXhang/ddh-ultrasound-crop --draft --target master --title "DDH 图像裁剪 v0.5.0" --notes-file data/publication/release_notes.md
gh release upload v0.5.0 ../release/v0.5.0/DDH_Crop_Setup_0.5.0_CPU_x64.exe --repo L1NXhang/ddh-ultrasound-crop
gh release edit v0.5.0 --repo L1NXhang/ddh-ultrasound-crop --draft=false
```

示例只展示流程；实际发布还必须上传 GPU 安装 EXE 和校验文件；只有使用 --split 时才需要额外上传全部分卷。不要把大型安装包提交到 Git 仓库或在 Release 说明中写入账号密码。

清理当前版本中的敏感信息不会自动清除旧 Git 历史。历史中出现过的口令应作废；如果要删除旧历史中的内容，需要单独安排历史清理与协作者同步，不能直接强制覆盖主分支。
