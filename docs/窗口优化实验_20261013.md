# 窗口定位与坐标流程实验（2026-10-13）

## 本轮结论

完成两轮窗口检测器微调、规则对照、已知布局匹配原型和裁剪工具坐标修正。
尚不能用学习检测器直接替换现行规则：新设备规则的像素精度更高，学习模型适合作为候选和交叉检查。
布局匹配原型覆盖率过低，未接入正式工具。现用 `runs/window.pt`、`runs_v2/crop.pt`、原始图片和正式标签均未覆盖。

## 数据与实验协议

- 老数据沿用 `data/reports_v2/split.jsonl` 的四份划分：train 560 / val 128 / calib 86 / test 88。
- 新数据仅使用 `data/分配20261009.jsonl` 中 `crop_source=human_tool` 的 89 条确认记录。
- 新数据按报告中的已知近重复对、解码像素完全重复合并后划分，seed=20261013：train 52 / val 18 / test 19。
- 新测试集只用于报告；模型按验证集选点。后续若依据这些测试结果调参，应将这批视为开发数据，另留新测试集。
- 19 张只是对本轮学习训练留出；现行规则此前的开发和人工验收可能已使用这 89 张，因此不是所有方法共同未见的独立测试集。
- 第一轮直接用旧划分清单的窗口参考；发现该版本与逐图修正清单不同后，第二轮按 ID 取 `train_ready_v2.jsonl` 的窗口，仅在实验副本中替换，划分不变。
- 旧窗口含模板/算法派生参考，不能当作独立专家真值。新窗口也由预填工具确认，可能有锚定偏差。
- `review_new_v4.jsonl` 窗口曾被当前规则算法刷新，排除，避免以算法输出证明算法正确。
- 余的旧裁剪标签不参与训练。未知批次、备份及未经审核的自动建议不作为真值。
- 没有患者标识；已知重复分组不能保证患者独立性。本轮为探索性工程实验。

## 训练设置

使用已有 Faster R-CNN MobileNetV3 FPN 窗口权重初始化，冻结 backbone，训练 RPN 与 ROI 检测部分。
原输入短边 640 设置保留，batch=2，AdamW lr=3e-5，weight_decay=1e-4，6 epochs。
新设备训练样本采样次数为旧图的 4 倍，采用已有亮度增强与同步框坐标的水平翻转。
验证目标为老/新两域各自 mean(1-IoU) 的等权平均；无唯一高分窗口按 IoU=0 计入。
RTX 4060 Laptop GPU，第一轮约 217 秒，第二轮约 170 秒；均选中 epoch 5。

另一个 26px 左边界偏差案例，第二轮模型仍偏差 31px；学习模型也不是特例万能解。

## 布局匹配原型

`tools/layout_profiles.py` 仅从 train 分组建立布局候选：同尺寸、窗口坐标组内跨度≤16px、至少 3 个参考。
共建立 8 个候选配置：4 个 1280×960、4 个 1024×768。比较窗口外的低分辨率灰度外观。
候选距离阈值 0.12，歧义间隔 0.02，未按测试集调整；尺寸不支持、界面不相似或多模板含糊时返回 unknown。
所有候选固定要求人工复核，不代表设备身份，也不自动批准裁剪。

新 val 18 张仅匹配 5 张，新 test 19 张仅匹配 2 张；老数据因候选歧义全部退回未知。
新 test 匹配的两张四边均≤1px，但样本极少，覆盖率 10.5%，不能作为准确率保证。
同一设备可能有多个缩放/深度模式，外围 UI 相似而窗口不同；内部标签变化也可能被外围描述遗漏。
因此原型未部署。下一步应在窗口学习检测与布局配置共同约束下验证路由，而不是放宽阈值强行匹配。

## 坐标原理与实际验证

1. 原图坐标中的窗口为 `[x0,y0,x1,y1]`，高度 `H=y1-y0`。
2. 从原图取窗口，灰度三通道、保持比例缩放并填充到模型输入尺寸。
3. 模型输出窗口内归一化上下位置 `rt,rb`。网络已将输出定义在窗口坐标中，不再减一次填充量。
4. 转回原图：top=floor(y0+H*rt)，bottom=ceil(y0+H*rb)。工具默认先在两侧扩 0.02 的归一化边距，再夹到 [0,1]。
5. 最终直接从原图裁 `[x0,top,x1,bottom]`，不将缩放过的模型输入作为成品。

数值示例：y0=100，H=600，rt=0.25，rb=0.85，不加边距时为原图 y=250、610；默认 2% 边距时为 238、622。
window 高度错会影响换算比例；window 左右错也可能改变模型看到的内容与预测。
实际用同一图片、同一现有裁剪权重、相同随机种子验证（含默认 2% 边距）：

| 输入窗口 | 模型最终原图上下线 |
|---|---|
| 人工 `[188,74,832,723]` | `[258,611]` |
| 错误规则 `[189,74,660,723]` | `[264,618]` |

这证明窗口修改后需要重新运行模型，而非只移动红框；以上不是对这张图裁剪口径正确性的独立评估。

## 已修正的工具行为

- 浏览器增加按钮与 R 键：按当前窗口重新预测上下裁剪线。
- 窗口修改后，前端与后端均阻止保存旧窗口下的预测；重新预测后可继续人工微调。
- 原始预测窗口、原始预测裁剪线、最近一次重新预测、最终坐标均保留。
- 分别记录 window_modified、crop_modified 及像素变化，modified 不再由点击行为直接决定。
- 保存前验证整数、有限数、原图范围和裁剪顺序；拒绝越界与空裁剪。
- JSONL 先写临时文件再替换；dry-run 不再写结果清单。
- 将“窗口置信度”改为规则状态提示，避免把启发式赋值表述为正确概率。
- 浏览器显示文件名和错误内容时转义 HTML；保存和推理中的重复操作被阻止。

## 建议下一步

先对新设备严重失败和不同缩放模式建立独立窗口复核集，尤其包含灰度条、内嵌标签和深部暗带。
以规则、学习模型、布局候选分歧筛选人工复核；同时随机抽查无告警样本，不能只检查已被发现的错误。
在验证集上确定候选选择与拒绝规则，再在新留出集评价准确性、覆盖率和人工修改时间。
嵌入成像区的文字/灰度条与真正窗外 UI 不同，矩形窗口无法在不损失图像内容的前提下消除全部内部覆盖物。
学习窗口模型可以利用布局与纹理信息，但不能保证处理从未见过的设备或覆盖方式。
