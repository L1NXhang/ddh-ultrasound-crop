# 裁剪工作台编辑体验更新

本轮针对换图丢失调整、误拖无法撤销、重启需要重新找目录的问题，补充了独立草稿、撤销重做、成品预览和最近任务入口。界面继续使用已有米白、暖灰和深色按钮，新增操作集中在图片顶部。

## 数据约定

`drafts/<id>.json` 只保存未确认的窗口与四边坐标、原图哈希、所依据的已确认版本、初始和最近一次模型预测。草稿由后端保存模型来源，前端只提交调整坐标。文件通过临时文件、fsync 和原子替换写入。

草稿恢复需要原图哈希和已确认版本均匹配。确认保存后清理对应草稿；即使清理之前意外退出，下一次也会因版本不匹配而忽略旧草稿。批量处理跳过含草稿的图片，避免覆盖人工调整。已审核图片的新草稿仍出现在待审核队列。

草稿不导出成品、不改写人工确认记录、不增加训练候选、不进入 ZIP。人工确认后仍保持 `approved_for_training: false`，由后续复核决定是否用于训练。

## 操作与退出

四边调整后延迟 350ms 保存；换图和切换任务前立即等待保存。保存失败保留当前图片并提示重试。Windows 关闭窗口时，先等待进行中的界面操作与草稿保存，再停止后台服务；失败则留在软件内。

撤销最多保留单张图片本次打开期间的 40 个状态，支持 Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y。恢复预测也进入撤销历史。撤回窗口修改后，如果窗口与最近一次预测不一致，仍要求重新预测。成品预览只改变显示，保留原图坐标和导出逻辑。

最近任务最多 6 项，以图片目录与保存位置去重。测试会还原最近任务文件，避免把临时合成图片目录留给实际用户。

## 验证

- 76 项单元/集成测试通过，新增草稿恢复、来源变化、旧版本失效、异常文件、批量保护、已确认图片的新草稿，以及 API 会话校验等用例。
- 浏览器实际流程验证撤销、重做、预览、换图/刷新恢复、最近任务、写入失败重试和退出前保存；原有人工/自动裁剪和 ZIP 流程也通过。
- 实际 EXE / WebView2 / CUDA 验证原生目录选择、裁剪、ZIP 另存为、关闭前写入未确认草稿及后台进程退出。
- 六个 Python 后端模块行覆盖率合计 82.7%（586 / 709），不包含前端和 C#。记录在 `data/desktop_build/session_backend_coverage.json`。

使用说明见 `裁剪工作台使用说明.md`。这轮没有修改生产模型权重或将成员标注直接投入训练。桌面版仍依赖当前项目运行环境，尚未制作可独立分发的安装包。
