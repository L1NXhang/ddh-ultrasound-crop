# DDH 裁剪工作台

双击 **`D:\ddhmodel\DDH裁剪工具.exe`**，即可打开独立的 Windows 桌面软件。裁剪界面内嵌在软件窗口里，目录选择和压缩包另存为使用原生对话框；无需手动打开浏览器或终端。`启动裁剪工具.bat` 也已改为启动这个桌面版。

程序默认最大化，有独立图标和任务栏入口。再次双击会激活已有窗口。关闭软件时，会完成当前正在处理的图片，保存结果，然后关闭本次模型服务并释放资源；剩余图片可以下次继续。未确认的人工调整会独立保存为草稿；点击“保存并下一张”才导出成品并记为人工审核。

桌面版验收状态（2026-10-14 更新）：独立窗口、单实例激活、原生目录选择、CUDA 预测、人工四边调整、自动批量、ZIP 落盘和原生另存为已通过实际流程测试。此前未完成的“取消另存为后退出”也已补验收，软件窗口和本次 Python 模型进程均正常退出。记录位于 `data/desktop_build/acceptance.json`。

界面已改为米白底、细分隔线和深色按钮，中文标题使用本机 Noto Serif SC，操作文字使用 Noto Sans SC / Segoe UI，文件路径使用等宽字体。主界面保留图片列表、裁剪范围和保存操作；像素坐标及训练记录说明按需展开。

工作区根目录的 EXE 是与当前 GPU 项目环境配套的本机运行版，不能只把这个 EXE 单独发给其他电脑。**给成员分发请用 `D:\ddhmodel\release\DDH裁剪工具_Windows_x64_CPU_v0.3.2.zip`**：已包含 CPU 推理环境、模型和离线浏览器组件，不包含项目图片或标注。完整解压后选择自己的图片目录即可。详见 [便携版分发说明](便携版分发_20261015.md)。需要自动使用 GPU 时，可选 `D:\ddhmodel\release\DDH裁剪工具_Windows_x64_CPU_GPU_v0.4.0.zip`（约 2.56 GiB），兼容 NVIDIA CUDA 时使用 GPU，否则使用 CPU。详见 [CPU/GPU 通用版说明](CPU_GPU通用版分发_20261015.md)。

## 本次更新（2026-10-15）

- **草稿恢复**：拖动四边后自动保存；换图、切换任务和正常退出前会等待写入。重新打开相同图片目录和保存位置即可恢复。草稿写入失败时会提示重试，并保留当前图片。
- **撤销与重做**：顶部箭头按钮，或 `Ctrl+Z` / `Ctrl+Shift+Z`（也支持 `Ctrl+Y`）。单张图片本次打开期间保留最近 40 个调整状态；关闭后恢复最终草稿，撤销历史不跨会话。
- **恢复预测**：恢复最近一次模型建议，仍可撤销。窗口与最近预测不一致时，仍需按 `R` 重新预测后确认。
- **成品预览**：顶部“成品预览”或 `P`，显示最终裁剪区域，不带框线；再次按 `P` 或 `Esc` 返回原图。
- **最近打开**：首页展开“最近打开”，选择任务继续审核，最多保留 6 个“图片目录 + 保存位置”的组合。

批量模式会保留已有人工草稿，继续处理其余未导出的图片。已审核图片若产生新草稿，也会重新出现在待审核队列；此前确认过的成品仍然保留，直到再次确认生成新版本。

草稿按原图 SHA256 和已确认版本匹配；原图发生变化、或已有更新的确认版本时，旧草稿不会覆盖当前状态。草稿不计入审核数量、不进入训练候选，也不打进结果 ZIP。

最终版本通过 76 项单元/集成测试、原有浏览器流程、新增编辑流程和实际 Windows EXE / WebView2 / CUDA 验收。六个 Python 后端模块的单元/集成行覆盖率为 82.7%，不包含前端和 C# 外壳。验收仅使用隔离的合成图片，不代表模型在新设备上的准确率。覆盖率记录：`data/desktop_build/session_backend_coverage.json`。

## 开始一批任务

1. 选择“图片文件夹”：读取该目录及子目录中的 JPG、JPEG、PNG、BMP。
2. 选择“保存位置”（工作目录）：裁剪结果、JSON 和可选的压缩包保存在这里。请选择图片文件夹之外的位置。
3. 选择一种方式：
   - **逐张审核**：逐张展示模型建议，确认或调整后保存。
   - **批量裁剪**：直接保存每张图片的预测结果；没有检测到窗口或处理失败的图片会留下错误记录，供人工处理。

同一图片文件夹和工作目录再次打开时，会恢复已经保存的进度和未确认草稿。也可以在首页展开“最近打开”直接继续。自动模式只处理尚未成功导出的图片；人工模式优先显示尚未人工确认的图片。首次预测需要加载模型，可能等待数秒；有可用 CUDA GPU 时自动使用 GPU。

## 人工审核

- **红框是完整成像窗口**；**绿色矩形是最终导出范围**。
- 通常直接按 **Enter**，保存并进入下一张。
- 按 **C** 或点“裁剪范围”，拖动绿色框的左、右、上、下边，可裁掉边缘的设备文字、图标。请以关键解剖结构完整保留为准。
- 红框明显不对时，按 **W**：可拖动红框边界，也可在图内重新拖出窗口；随后按 **R** 重新预测，再调整绿色框并确认。
- **K** 或“稍后处理”：本次先跳过。可切换“全部图片”再查看；重新打开项目也会再次进入待审核队列。
- **↑ / ↓** 微调绿色框上边界 1 像素，按住 **Shift** 为 10 像素。四条边均可用鼠标拖动。

侧栏可切换“待审核 / 全部图片 / 已审核”。已保存的结果也能重新打开修改，每次保存保留一个新版本。

自动批量任务支持“处理完当前图片后停止”。已完成结果仍然保存，再打开同一项目可继续处理余下图片。

## 保存和压缩包

人工模式每次确认即保存；自动模式每处理成功一张即保存。输出路径显示在左侧，点击“打开结果文件夹”可进入。

```text
<工作目录>/DDH裁剪结果/<来源文件夹名_标识>/
  cropped/                              裁好的 PNG，按原图像素导出
  annotated/                            原图加窗口和最终框，供核对
  drafts/<图片标识>.json                 未确认草稿，独立于成品和训练记录
  project.json                          来源目录和项目元信息
  results.jsonl                         每张图片当前最新的结果
  review_history.jsonl                  历次保存和失败记录
  reviewed_training_candidates.jsonl    人工确认的训练候选
```

最近任务入口存放在程序目录的 `data/studio_runtime/recent_projects.json`，仅记录本机路径和进度，不复制原图。原图保持原样。重名图片使用文件标识区分；复改的图片保留版本号，`results.jsonl` 指向当前版本。

完成一批后会询问是否另存 ZIP，也可随时点侧栏“保存压缩包”。只有点击“保存压缩包”才生成文件，保存到 **`<工作目录>/DDH压缩包/`**。ZIP 收录当前版本的成品、标线图和三份项目/结果/候选文件；原图和完整历史文件不打入 ZIP。点击“另存压缩包副本”，可在 Windows 保存对话框中选择额外保存的位置。

## 人工反馈如何用于训练

每张记录包含原始图片路径、文件 SHA256、原图尺寸、模型版本、初始预测、按修正窗口重新预测的结果、最终窗口和四边裁剪坐标，以及是否人工确认、是否修改。坐标使用 **原图像素**，矩形为 `[左, 上, 右, 下]`，右/下为不包含端点的边界；网页缩放不会改变保存坐标。

自动预测标记为 `human_reviewed: false`；人工点击确认后，标记为 `human_reviewed: true` 并进入 `reviewed_training_candidates.jsonl`。两类结果的 `approved_for_training` 都先设为 `false`：候选还需复核、去重、按同源图片分组并划分训练/验证/测试集，再纳入下一轮训练。这样可以保留人工反馈，避免模型用自己的错误预测反复训练。

此版产品接入现有 `runs_v2/crop.pt` 和成像窗口检测规则。**图像内部文字/图标的自动检测与自动左右裁剪尚未训练**，当前由人工调整最终框解决；单个矩形无法去掉图像中心的遮挡而同时保留四周全部结构。
